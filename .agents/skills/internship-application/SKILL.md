# 实习申请准备

这是现有本地 V1 程序的跨任务入口，不是邮件发送程序。

## 定位本地档案

读取 `$HOME/.config/internship-application-agent/local.toml` 中 `[paths]` 的 `project_root` 和 `case_dir`。该文件仅留在用户电脑，不属于技能或代码仓库。若文件不存在或路径失效，先请用户指出求职档案；不要猜测另一位求职者的资料。仅在可访问该档案的本地任务中运行程序。

先读 `project_root/AGENTS.md`、`project_root/README.md`，以及案例中的 `接续说明.md`、`brief.yaml`、`profile.yaml`、`简历制作规范.md` 和当前岗位相关的经历、简历、投递记录。按需使用 `job-ok` 技能的证据规则。既有程序说明在 `project_root/internship-agent-v1/README.md`，实际配置在 `case_dir/agent-v1/config.local.toml`。

## 处理岗位

1. 仅处理用户指定的公开链接、页面、截图或粘贴的 JD；保存原文与来源。一篇文章含多个岗位时，逐岗位拆分，同一文章链接不能单独作为“重复岗位”的依据。
2. **先查重，再生成。** 用公司、岗位、投递邮箱与来源核对 `application-tracker.csv`、`jobs.jsonl` 及已知已发送记录。若已投递，报告原记录；除非用户明确要求重新申请，不再运行会重新生成该岗位草稿的 V1 流程，也不覆盖原投递简历版本。
3. 提取地点、截止日、院校/毕业年份、到岗时间、每周天数、实习时长、邮箱、邮件主题及附件命名规则。把硬性要求和可协商条件分开；匹配分数仅用于初筛，不代表录取概率。
4. 对未投且信息足够的单个岗位，先运行 V1 的 `doctor`，再按程序说明处理该来源。程序不适合直接处理的复合文章或字段不明的 JD，改为逐岗位人工核对；不要让解析结果覆盖已经确认的事实或投递状态。
5. 定制简历只允许根据档案证据取舍、排序、压缩和改写，遵循案例的简历制作规范；缺少依据的经历、数字和技能不得进入正式版本。生成或修改 Word/PDF 后核对内容、附件名称与页面效果。
6. 交付时展示收件人、主题、正文、实际附件、硬条件缺口和台账状态。默认停在发送前。只有用户看过具体材料并明确确认，才可按当前任务允许的方式执行外部发送；发送成功须有可核实记录，方可标记“已投递”。V1 自身没有邮件发送功能。

## 隐私边界

个人定位配置留在本机；简历、招聘原文、邮件和台账留在本地求职工作区，均不进入代码仓库。对外展示或同步技能时，只使用不含个人路径、姓名、联系方式及申请记录的通用 `SKILL.md`。
